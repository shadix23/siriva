# Задание: прогон TRIBE v2 на ПК пользователя

Железо: RTX 5060 (8 ГБ видеопамяти), Ryzen 5 5600, 32 ГБ ОЗУ. Исполнитель: сессия Claude Code на этом ПК (Remote Control). Постановщик: главная сессия проекта Es на Mac.

## Цель
Заменить заглушку матрицы нагрузки `es/backend/es_core/data/load_matrix.placeholder.json` настоящей «предсказанной нагрузкой» TRIBE v2 для всех упражнений из `es/backend/es_core/data/exercises.json` (25 шт.).

## Контекст (прочитать первым)
- `es-mvp-plan.md`, раздел «Матрица TRIBE v2».
- `es/docs/RESEARCH-ACCESS-TRIBE.md`: что за модель, входы и выходы, лицензия, таблица «домен -> сети и зоны».
- `es/backend/es_core/matrix.py`: формат, который читает бэкенд (`JsonMatrixLoader`).

## Шаги
0. **Железо.** `nvidia-smi`: драйвер и версия CUDA. RTX 50xx (Blackwell, sm_120) работает только с PyTorch на CUDA 12.8+ (колёса cu128, torch 2.7 и новее). Если зависимости TRIBE v2 не ставятся на Windows нативно, работать в WSL2 Ubuntu. Окружение: `es/tribe/.venv`.
1. **Доступ к моделям.** `facebook/tribev2` и `meta-llama/Llama-3.2-3B` на Hugging Face могут требовать принятия лицензии. Лицензию принимает сам пользователь в браузере и сам выполняет `huggingface-cli login`. Токен за пользователя не вводить, в репозиторий и в файлы проекта не писать. Нет доступа - остановиться и коротко написать, что нужно сделать пользователю.
2. **Установка.** TRIBE v2 по официальной инструкции (model card или репозиторий), проверить на их демо-примере.
3. **Стимулы.** Для каждого упражнения собрать стимул того, что воспринимает человек (инструкция и материал), 20-60 секунд:
   - речевые и слуховые: аудио (офлайн TTS) и текст с таймингами слов;
   - зрительные и пространственные: видео экрана задания, сгенерированное кодом (статичный кадр или простая анимация).
   Записать `es/tribe/stimuli/manifest.json` (id упражнения, модальности, длительность, как получен) и скрипт генерации. Большие медиафайлы в git не класть (см. `.gitignore`).
4. **8 ГБ видеопамяти.** Модальности по очереди: текст, потом аудио, потом видео. Признаки кэшировать на диск (`es/tribe/cache/`), между экстракторами освобождать видеопамять. Llama-3.2-3B в bf16 или 8-bit, батч 1, при нехватке выгрузка на CPU (32 ГБ ОЗУ). Если V-JEPA 2 Giant не помещается даже с уменьшенными клипами, зрительные стимулы считаются без видеопути и это явно пишется в отчёт. Значения не подменять.
5. **Агрегация в домены.** Выход 1 Гц, кора fsaverage5 и подкорка. Первые ~5 секунд отбросить (гемодинамический сдвиг). Сопоставить зоны с пятью доменами по таблице из `RESEARCH-ACCESS-TRIBE.md` (атласы через nilearn: Yeo, Glasser или Harvard-Oxford - что получится). Для каждого стимула: средний отклик в зонах домена, z-оценка по всем стимулам, перевод в 0..1. Метод записать.
   - `processing_speed`: только прокси темпа стимула (слов в секунду, смен кадра в секунду), с пометкой, что это не мозговая величина.
   - `episodic_memory`: с пометкой о низкой надёжности.
6. **Выход.** `es/tribe/out/load_matrix.tribe_v2.json` в формате `JsonMatrixLoader`: `source` = "TRIBE v2 predicted load", `label_ru`, `model_version`, `atlas`, `domains` (ровно 5, как в заглушке), `domain_notes`, `loads` {id упражнения: {домен: 0..1}} для всех id из `exercises.json`. Проверка: в `es/backend` команда `ES_LOAD_MATRIX=<путь к матрице> python -m pytest` проходит. Если тесты завязаны на значения заглушки, сообщить, тесты не править.
7. **Валидация (метрика успеха №2 плана).** Корреляция Спирмена по каждому домену между матрицей TRIBE v2 и заглушкой (априорная разметка по типу задания). Таблица в отчёте.
8. **Отчёт** `es/tribe/REPORT.md`: железо и версии, время прогона, что не поместилось, таблица корреляций, ограничения (модель обучена на 25 здоровых взрослых, моделирует восприятие, а не продукцию речи), атрибуция и лицензия CC BY-NC (только некоммерческий прототип). Без длинных тире, только дефис.

## Границы
- Работать в ветке `es-tribe`, пушить только её (`git push origin es-tribe`). В `main` не пушить.
- Не трогать `es/backend/`, `es/web/`, файлы карты Obsidian.
- В git: код, `manifest.json`, матрица, отчёт. Без весов моделей, кэшей, `.venv` и больших стимулов.
- Секреты (токен HF и любые ключи) не коммитить.

## Готово, когда
Ветка `es-tribe` запушена, в ней `es/tribe/out/load_matrix.tribe_v2.json` проходит загрузчик бэкенда, `REPORT.md` с таблицей корреляций и честными ограничениями.

## Обновление 14.11.2026, 21:15: версия v2 «на максималках»
Первый прогон на Mac (es/tribe/REPORT-mac.md) не дал согласованности. Причины: русская озвучка, у зрительных заданий был только звук инструкции, короткие клипы, нет видео. Поэтому на ПК делаем так:
- Стимулы на **английском** (язык обучения модели), 25-35 с, на **настоящем содержании** задания. Рассказ: lantern-keeper-en (`es/backend/es_core/stories.py`). Картинки: `es/web/public/pictures/*.jpg`. Для зрительных и моторных заданий **видео** хода задания и короткая английская инструкция. Тайминги слов брать из распознавания (faster-whisper), а не по длине текста.
- **Все три модальности** на видеокарте: аудио, текст (Llama-3.2-3B из открытого зеркала `unsloth/Llama-3.2-3B`, пользователь принял Llama 3.2 Community License, вход в HF не нужен), видео (V-JEPA 2). При 8 ГБ модели держать по одной, признаки кэшировать.
- Скрипты Mac-прогона в `es/tribe/mac/` (стимулы, агрегация, атласы, валидация) взять за основу и заменить устройство на cuda.
- Валидация: Спирмен против заглушки по доменам и «известные группы» (у речевых заданий word_access и phrase_building выше, у зрительных attention выше; Mann-Whitney, размер эффекта).
- Выход: `es/tribe/out/load_matrix.tribe_v2.pc.json`, отчёт `es/tribe/REPORT-pc.md`, ветка `es-tribe`.
